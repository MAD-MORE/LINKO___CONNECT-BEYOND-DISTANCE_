# Phase 2.18 — Requirements Baseline

## Baseline rule
The approved Phase 2 requirement set becomes the controlled reference for architecture and implementation. Changes after baseline require a documented change request and impact analysis.

## Baseline Contents

- Product scope and actors
- Functional requirements
- Non-functional requirements
- Connectivity/networking requirements
- Android requirements
- Security requirements
- Privacy requirements
- Data requirements
- Backend/infrastructure requirements
- Reliability/availability requirements
- Performance/resource requirements
- Abuse-prevention requirements
- Business/monetization requirements
- Compliance/store requirements
- Traceability matrix
- Verification/acceptance criteria

## Requirements

- BAS-001 P0 — Baseline version shall have a unique version/date.
- BAS-002 P0 — Approved documents shall be immutable by ordinary implementation work.
- BAS-003 P0 — Changes shall identify affected requirements and downstream artifacts.
- BAS-004 P0 — Security/privacy P0 requirements may not be weakened without explicit risk acceptance.
- BAS-005 P0 — Architecture shall trace back to the baseline.
- BAS-006 P0 — Implementation scope shall not silently expand beyond baseline.
